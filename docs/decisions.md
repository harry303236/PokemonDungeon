## 2026-10-21 Build framework: talents, support gems, move variants, statuses/reactions (ADR)
- **Data-driven**: talents (`src/data/build/charmander-talents.json`, copied verbatim), gems, move tags, skill upgrades/variants, statuses and reaction rules are JSON in `src/data/build/`. Code holds only generic handlers.
- **Fixed modifier order** (`src/core/build/pipeline.ts`, `STAGES`): 1 variant → 2 shape (multi-proj, fork, extra beams) → 3 prehit (pierce) → 4 onhit (chain, ignite, statuses) → 5 reaction → 6 numeric (% inc / more). Every cast builds a `MoveSpec` by running all sources (upgrades, socketed gems, talents, equipment affixes) through the stages; tag compatibility is evaluated against the spec's tags *when that stage runs*, so a variant that adds `area` unlocks area gems/reactions.
- **Data ops**: modifiers are lists of ops (`add`/`mul`/`set`/`addTag`/`removeTag`/`param`/`applyStatus`/`disableReaction`); unknown op/field/stage → console.warn once, ignored.
- **Projectile resolution order on hit**: pierce → fork → chain → expire (so pierce+chain = pass through N, then bounce M).
- **Talents**: `requires` = ALL listed parents (the design file's mid/keystone nodes list two parents; ANY would make the tree trivially shallow). Evo gating uses data stages 1/2/3 = Charmander/Charmeleon/Charizard. Points = (level−1)×pointsPerLevel capped at totalPoints (+ debug bonus). exclusiveGroup = at most one node per group (one keystone). effectType registry `TALENT_EFFECTS`; unknown types warn once, no crash.
- **Respec**: free before meta.respec.freeBeforeLevel (16); after that per-rank refund costs 1 `ash_shard` (new currency, 6% monster drop, boss 100%); full reset costs level×100 gold (gold from kills). Refund blocked if an allocated child still needs the node.
- **Sockets** are stored per MOVE id (not per slot), count = meta.socketsPerMoveByEvoStage; gems therefore travel with a move when slots are rebound. Incompatible gems are refused at socket time (tags).
- **Equipment affixes** (extra-projectile, pierce, split-flame) were moved into the pipeline as modifiers so they compose with gems.
- **Statuses/reactions**: generic `entity.statuses` + `reactions.json` rules `{trigger tags, requires status, consume, effect}`; example: Ember applies `ember-seed`, any `area`+`fire` hit detonates it into a burst (bursts don't re-trigger reactions; chain context guards loops). Ground statuses: extension point only (not implemented yet).
- **Per-skill upgrades (D4-style)**: `skill-upgrades.json` → choice groups per move, each option is a pipeline modifier (any stage). Example pair: Flamethrower `ft-sustained` (longer, widens over life) vs `ft-burst` (short, end explosion, gains `area` tag → can detonate ember-seed).

### Director content wiring (charmander-moves-gems.json)
- Director file is copied verbatim to `src/data/build/`; `director-bindings.json` holds the executable side (ops/flags per variant & gem, hook/trigger/requires/effect per reaction, VFX keys). Loader validates: modifierOrder must map 1:1 onto engine STAGES, every variant/gem/reaction needs a binding (missing → loaded as STUB, warn once, shown "(未實裝)" in UI), no orphan bindings. Director tags override `move-tags.json`; director move ids map via `moveIdMap` (fire_spin→fire-spin, fire_blast→fire-blast, flame_charge→flare-blitz).
- Supersedes my earlier example content (gems.json, skill-upgrades.json, ember-seed status rule). Gem ids are now the director's (multi, pierce, chain, fork, delayed, aoe, ignite, energy_on_kill); `aoe` requires `area` only (no longer beams).
- New generic engine pieces: `MoveSpec.flags` (+ `flag` op), `ground` entities (seed / burning ground), statuses root/stun/fire-vuln/marked, sticky delayed-blast marks, zone follow, blast→radial bolts, dash trail/pull, reaction hooks `hit|dash|chain|ground`, `sunT` weather timer.
- Interpretations: ft_focus = narrow long beam that keeps the beam carrier but gains `projectile` (so chain/fork/multi gems fit); chain on beams jumps from the farthest target hit each tick. ft_spread = 5-beam fan, short, leaves 2 burning-ground patches per beam. fb_meteor = +0.6 s delay, +60% dmg. fb_star = blast at 60% + 5 radial bolts (projectile gems apply to the bolts). fc_ram pulls within 140 px to 28 px of landing, stun 0.8 s (bosses too, for now).
- Sun (大晴天) has no in-game source yet (likely sunDurationPct talents / ks_solarPower keystone); debug Shift+K sets 15 s.

### Director update 23:10 + rulings
- Repo copy re-synced: `requiresTags` → `requiresAnyTags` (loader validates presence); modifierOrder is now 7 stages → engine `STAGES = variant, shape, prehit, settle, onhit, status, numeric` (validated 1:1 via `stageMap`). Ignite / burn-chance (gem + talent) moved to `status`.

## ADR: Utility branch + caps
- 通用 branch (11 util_* + 2 bridge_*) synced from the director file. Layout per meta.ui.utilityBranchLayout: subtrees off root spread left/right below the main columns (balanced by subtree size); bridges via `uiPlacement: between:a|b`; `requiresAny` = any one parent.
- Bridge `evoStage: 16` is not a stage number; it equals evoStageUnlock['2'], so it is read as a minimum level (validator accepts stage numbers or unlock levels).
- Caps (meta.mechanics) are applied after summing ALL modifiers: move speed (talents + post-dodge buff), CDR (global + per-move), damage reduction (all damage-taken sources summed additively, e.g. 耐熱體質 + 毅力). Tooltips show the effective post-cap total and flag when capped.
- 戰鬥節奏 limiter: `onKillCdRefundMaxPerFrame` (1) and `onKillCdRefundMaxSecPerSec` (1.5, rolling 1 s window) — added to meta.mechanics in both repo and director copies.
- Click-to-move moves exactly to waypoints (budget clipped at waypoint), so higher speed cannot overshoot; covered by a test at > cap speed.
