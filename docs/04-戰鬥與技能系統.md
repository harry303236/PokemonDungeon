# 04 戰鬥與技能系統

本文件的數值都是 MVP 預設值，集中放在 `src/core/balance.ts`（`BALANCE` 常數物件），不准散落在程式各處。

## 1. 能力值
寶可夢公式（IV=15、EV=0、無性格）：
- `HP_stat = floor((2*B + 15) * L / 100) + L + 10`
- `X_stat  = floor((2*B + 15) * L / 100) + 5`
ARPG 換算：
| 遊戲數值 | 公式 |
|---|---|
| maxHp | `HP_stat * 4` |
| atk / spa / def / spd | 直接使用 X_stat |
| moveSpeed (px/s) | `140 + speed_stat * 0.6`（上限 320） |
| critChance | 基礎 5%；高要害招式（meta.critRate ≥1）為 15% |
| critMult | 1.5 |
怪物使用同一套公式，再乘上 `MonsterData.hpMult`；Tier 加成：HP ×`1.15^(tier-1)`、傷害 ×`1.08^(tier-1)`。

## 2. 傷害公式（改編自正作）
```
base = ((2*L/5 + 2) * P * A / D) / 50 + 2
dmg  = base * STAB * typeEff * weatherMult * critMult * rand(0.9,1.0) * Π(additive buckets) * Π(multipliers)
```
- `P` = 招式 power ×（技能樹 rank 加成 `1 + 0.1*(rank-1)`）；多段招式每段用 P/hits。
- `A/D`：物理用 atk/def，特殊用 spa/spd。灼傷時物理 A ×0.5。
- `STAB` 1.5（招式屬性 ∈ 自身屬性）。
- 加成桶：同一桶內的 `add` 相加 → (1+Σ)；不同桶之間相乘。桶別：`typeBonus`（木炭等）、`generic`（技能樹被動）、`conditional`（猛火、天氣類被動）。`mul` 效果直接相乘。
- 持續性形狀（beam／zone）：每次 tick 的傷害 = 單次傷害 × `tickRate⁻¹ / duration` × 1.5（持續傷害補償）。
- 最小傷害 1。傷害數字四捨五入成整數。
- **命中**：沒有隨機的閃避判定。accuracy 改成形狀參數：投射物散佈角 `spread = (100-acc)*0.3°`；acc 為 null 時必中。範例：煉獄（acc 50）散佈 15°、速度 ×0.7。

## 3. 屬性相剋
- 18×18 表格由 build-data 從 PokeAPI `type/{id}.damage_relations` 產生（`type-chart.json`）。
- 倍率直接沿用正作：0、0.25、0.5、1、2、4。**例外：0（免疫）在 ARPG 中改為 0.25**，避免無法通關（見 ADR-009）。
- UI：效果絕佳會顯示黃色大字＋「效果絕佳！」，效果不好顯示灰色小字。

## 5. 招式執行
### 5.1 4 招配置
- 槽 1–4 各放 1 個 moveId（必須是技能樹已解鎖的招式）。普攻＝該線第一個攻擊招（小火龍：`ember` 火花），**不佔槽**，冷卻 0.35 s，不耗能量。
- 只能在城鎮或樓層之間的「營火」換招。
### 5.2 冷卻與能量
- `cooldown = cooldownOverride ?? 40 / pp`（秒）；再乘上 `(1 - Σcdr)`，cdr 上限 40%。
  例：火花 1.6 s、噴射火焰 2.67 s、煉獄 8 s、閃焰衝鋒 2.67 s、大字爆炎 8 s。
- **能量**：上限 100，每秒回 12（安全房 ×3）。`energyCost = energyCostOverride ?? round(power/5)`；變化招固定 15。例：噴射火焰 18、閃焰衝鋒 24。
- 施放條件：冷卻完成 且 能量 ≥ cost 且 沒有硬直。
### 5.3 施放流程（`move-executor.ts`）
```
requestCast(slot) → validate → emit move:cast(pre)（詞綴可修改 shape/cost）
 → castTime（可被畏縮／睡眠打斷；打斷時退還 50% 能量，進入一半冷卻）
 → spawn shape entities（projectile/beam/zone…，掛 Owner/MoveInstance）
 → recovery（硬直） → 開始冷卻
```
- **MoveInstance**：施放當下，把「招式資料＋behavior＋已套用的詞綴（TM＋全域 held＋被動）」快照成不可變物件，帶在生成的實體上。之後換裝備不影響已飛出的投射物。
- 特殊對應：「下回合無法行動」類招式（爆炸烈焰、加農水炮、瘋狂植物）→ recovery 1.8 s；反傷招（閃焰衝鋒 1/3）→ 用實際造成傷害的比例扣自身 HP（不會致死，最低留 1）；蓄力招（日光束）→ castTime 1.0 s，晴天時為 0；吸取招（meta.drain）→ 回復造成傷害的 drain%。

## 6. 詞綴系統（tag + listener）
### 6.1 套用時機
| 詞綴類別 | 套用點 |
|---|---|
| stat | 建立 MoveInstance 時，加進 stat 桶 |
| shape | `move:cast(pre)` 時修改 ShapeSpec |
| trigger | 註冊 listener（綁在施放者身上；只在 MoveInstance 符合 requires 時觸發） |
| reaction | 註冊 listener，條件通常是 `targetHasTag` 或 weather |
| cost | 修改資源規則（PP／能量／HP） |
### 6.2 事件與 payload（hook 點）
```ts
interface GameEventsMap {
  'move:cast':      { caster: EntityId; move: MoveInstance; phase: 'pre'|'post'; chain: ChainContext };
  'hit:pre':        { source: EntityId; target: EntityId; move: MoveInstance; dmg: DamageCalc /*可修改*/; chain: ChainContext };
  'hit:post':       { source: EntityId; target: EntityId; move: MoveInstance; dealt: number; isCrit: boolean; typeEff: number; chain: ChainContext };
  'status:applied': { target: EntityId; status: StatusId; source: EntityId; chain: ChainContext };
  'tag:applied':    { target: EntityId; tag: TagId; stacks: number; source: EntityId; chain: ChainContext };
  'tag:consumed':   { target: EntityId; tag: TagId; by: EntityId; chain: ChainContext };
  'entity:killed':  { victim: EntityId; killer: EntityId; cause: 'hit'|'burn'|'poison'|'toxic'|'bound'|'self'; move?: MoveInstance; chain: ChainContext };
  'weather:changed':{ from: WeatherId; to: WeatherId };
  'terrain:changed':{ cellKey: string; to: TerrainId };
  'tick:second':    { entity: EntityId };   // 每秒一次，給 ability（太陽之力扣血）
}
```
### 6.3 Tag
- `TagSet` 元件：`Map<TagId, {stacks, expiresAt, sourceId}>`。tag 不會自己造成傷害，只當反應的鑰匙。
- 內建 tag：`wet`（潮濕，5 s）、`scorched`（焦灼，灼傷時順便加上）、`seeded`、`marked`、`heat`（自身資源層）。
- 消耗一律透過 `consumeTag` action 完成，並 emit `tag:consumed`。
### 6.4 遞迴保護（必須實作＋測試）
```ts
interface ChainContext { rootId: number; depth: number; visited: Set<string /*affixId:entityId*/> }
```
- 玩家直接施放的招式 depth=0；由詞綴 action 產生的任何事件，depth+1，並繼承 rootId。
- **depth ≥ 3 時，不再觸發任何 listener。**
- 同一個 rootId 內，同一個 `affixId` 對同一個目標最多觸發 1 次（visited）。
- 每個 listener 有 `icd`（預設 0.1 s）；全域上限：每 tick 最多 64 個衍生 action，超過的丟棄並在 dev 模式警告。
- 衍生傷害（爆炸等）不會觸發 `shape` 類詞綴，也不會套用到 TM 專屬的 trigger（防止自我循環）。
### 6.5 MVP 詞綴（小火龍線 10 個＋共用 8 個）
專屬（requires lines: charmander-line）：
| id | 類別 | 效果（EffectSpec 摘要） |
|---|---|---|
| split-flame 分裂炎 | shape | flamethrower：beam → 3 道 beam，夾角 25°，每道長度 ×0.6、傷害 ×0.5 |
| fire-glyph 大字烙印 | shape | fire-blast：落點 spawnZone fire-field r 100、4 s |
| ember-chain 餘燼連鎖 | trigger | listen entity:killed{cause:burn} → spawnExplosion r 80, 40%, fire＋套用 burn |
| eclipse-heart 日蝕之心 | cost（傳說） | solar-power 的每秒扣血改為每次施招扣 4% maxHp |
| dragonfire-resonance 龍炎共鳴 | trigger | dragon-dance 每層：下一個火招追加 castMove dragon-breath 50% |
| recoil-fuel 反噬燃料 | cost | flare-blitz 反傷不扣 HP，改為 grantStack heat；3 層時下一招必暴擊（但 heat 層存在時，受到的傷害 +10%/層） |
| homing-inferno 煉獄追蹤 | shape | inferno：homing 4 rad/s、spread 0、speed ×0.4 |
| steam-burst 蒸汽爆裂 | reaction | hit:post 火招 & targetHasTag wet → consumeTag，spawnExplosion r 90, 60%, blind 2 s |
| wildfire 燎原 | reaction | fire-spin 在 grassy 地帶上 r×2，並把地帶轉為 fire-field |
| all-in 孤注一擲 | cost | HP < 25%：能量消耗 0；同時無法被治療 |
共用（元素池）：`wet-mark`（水招命中 applyTag wet）、`kindling`（火招 +burn 15%）、`extra-projectile`（projectile count +1、spread 15°）、`pierce`（pierce +2）、`wide-arc`（arc-melee angle +40°）、`cdr`（stat：冷卻 -5~-12%）、`power`（stat：+8~20% 傷害）、`leech`（stat：造成傷害 2–5% 回血）。
### 6.6 範例：〔餘燼連鎖〕的完整流程
1. 噴射火焰命中 A → hit:post（depth0）→ 套用 burn。
2. A 因 burn 死亡 → entity:killed{cause:burn, chain.depth=0}。
3. ember-chain listener 觸發 → spawnExplosion（depth1）→ 命中 B、C → 套用 burn。
4. B 因 burn 死亡 → killed（depth1）→ 再次觸發（depth2）→ 爆炸命中 D。
5. D 死亡 → 衍生事件 depth3 → **停止**。
測試要驗證：10 隻怪站成一排時，最多連鎖 3 段；每個目標只會被同一個 affix 引爆一次。

## 9. 死亡與受擊
- 受擊後 0.4 s 無敵（只限玩家）。死亡時：失去本層掉落、扣 10% 金幣，回到城鎮；已拾取的物品保留（MVP）。
- 怪物死亡：XP = `baseExp(species) * L / 7 * xpMult`（baseExp 取自 API `base_experience`）。
